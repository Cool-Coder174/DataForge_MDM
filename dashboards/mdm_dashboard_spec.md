# Dashboard 3 — MDM Dashboard (QuickSight)

Shows master-data governance: golden records, duplicates, merges, and SCD2 history.

## Datasets

| Dataset | Source |
|---|---|
| `mdm_zone_scd2` | `${PROJECT_NAME}_master.dim_zone_scd2` |
| `mdm_vendor_scd2` | `${PROJECT_NAME}_master.dim_vendor_scd2` |
| `mdm_merge_history` | RDS `mdm.merge_history` (via Athena Federated Query or a CSV export) |

> If RDS federation isn't set up for the demo, export `merge_history` to
> `s3://$DATA_BUCKET/master/merge_history/` and crawl it, or screen-share the
> `GET /…/history` + `merge` API responses live instead.

## Calculated fields

| Field | Expression |
|---|---|
| `is_current_flag` | `ifelse({is_current}=true,1,0)` |
| `golden_zone_count` | `distinct_count({natural_key})` over `is_current=true` |
| `version_count` | `count({surrogate_key})` |

## Visuals

1. **Golden Record Count** — KPI: distinct `natural_key` where `is_current=true`
   (zones + vendors, two cards).
2. **Duplicate Candidate Count** — KPI sourced from the `/zones/match` and
   `/vendors/match` API (or a staged candidates table).
3. **Merge History** — table from `mdm_merge_history`: `domain`, `survivor_id`,
   `duplicate_ids`, `match_score`, `merged_at`.
4. **SCD2 Changes Over Time** — line/bar: x `valid_from` (by month), y
   `version_count` of non-current rows (history accumulation).
5. **Current vs Historical Records** — stacked bar: dimension domain
   (zone/vendor), groups `is_current` true/false, value `version_count`.
6. **Zone Version Detail** — table: `natural_key`, `zone_name`, `service_zone`,
   `is_current`, `valid_from`, `valid_to` (sorted by natural_key, valid_from) to
   visually prove history is preserved.

## Manual setup guide

1. Create datasets from the SCD2 Athena tables (Athena → SPICE).
2. Add calculated fields; build visuals 1–6.
3. For the live demo, pair this dashboard with the API calls in README §12:
   run `/zones/match`, then `/zones/merge`, then `/zones/{id}/history`, refresh
   SPICE, and show the new version row + merge entry.
4. Publish as **"DataForge — Master Data Management"**.

> SCD2 history is generated by `mdm/schema/seed_data.sql`, the MDM API `PUT`/
> `merge` operations, and `glue_jobs/scd2_upsert.py`.
